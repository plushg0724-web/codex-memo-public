# Mica 할 일 추천 펫

## 화면 v9 (2026-10-08): 바로 보이기 · 상태 알리기 · 단순한 패널

- **두 단계 요청.** 먼저 `taskPetSuggest({advice: false})`로 모델 설명 없이 순위만 받아 카드를 바로 그린다. 응답에 `advicePending`이 있으면 패널이 열려 있을 때만 설명을 한 번 더 요청한다. 엔진(`task-pet.cjs`)은 같은 대화·넘긴 목록·설정에서 60초 안에 고른 순위를 재사용한다. 그래서 두 번째 요청에는 설명 생성과 설명 뒤 원본 재확인 시간만 든다. 설명이 실패해도 이미 보인 카드는 지우지 않고 안내만 붙인다.
- **지난 결과 먼저.** 패널을 열면 지난 결과를 바로 보인다. 자료가 바뀌었거나 3분이 지났으면 카드를 둔 채 뒤에서 다시 확인한다. 머리말에 `다시 확인 중…`이 보이고, 새로 들어온 카드는 테두리로 표시한다. 같은 탭에서는 sessionStorage(`cxm-task-pet-result`)에 지난 결과를 둔다. 그래서 화면을 새로 고쳐도 배지가 바로 보인다(회색 = 다시 확인 필요).
- **닫힌 동안 자동 확인.** v8까지는 클릭할 때만 추천했다. 이제 닫힌 동안에도 순위만 다시 확인한다(모델 설명 없이). 주입 8초 뒤에 한 번 하고, 메모·라벨·현재 대화가 바뀌면 20초를 모아 한 번 한다. 실행 간격은 최소 60초이고, 그 밖에는 10분마다 한다. 숨긴 동안, 패널을 연 동안, 창이 가려진 동안은 하지 않는다. Mica는 같은 마지막 턴을 다시 묻지 않는다. 테스트에서는 `window.__cxmTaskPetAuto = false` 또는 `{prefetch, debounce, minGap, every}`로 조절한다.
- **펫 신호.** 크기를 62px에서 46px로 줄였고, 마우스·초점이 오면 1.25배로 커진다. 배지에는 보이는 할 일 수를 표시한다. 급한 일(답 대기·멈춤·오류·막힘)이 있으면 주황, 다시 확인할 때는 회색이다. 새 추천이 오면 배지 둘레가 깜빡인다. 표정도 바뀐다. 보통(웃음), 급한 일(눈을 뜸), 할 일 없음(잠, z), 오류(걱정)이다.
- **패널.** 머리말 한 줄에 `다음 할 일`, 확인 시각, ↻, ⓘ(추천 기준 펼치기), ⚙, ×를 둔다. ⚙는 바인딩 `{op: 'pet_settings'}`로 트레이의 펫 설정 창을 연다(`cdp_bridge.Bridge(on_pet_settings=…)`). 카드를 누르면 대화가 열린다(제목 단추를 카드 크기로 늘림). 넘기기는 카드 오른쪽 위 ×로 바꿨다. 개수 안내는 화면 읽기 프로그램에만 알리고, 오류·제한 안내만 화면에 보인다.
- **키보드.** Ctrl+Alt+P로 어디서든 펫을 열고 닫는다. 패널이 열려 있으면 숫자 1~6으로 해당 카드를 연다(입력칸에서는 무시). 열면 첫 카드에 초점이 간다.

## 업무 진척 보기 (2026-10-08)

패널 위쪽의 `다음 할 일 | 업무 진척` 전환으로 연다. 동작과 JSON 형식은 [task-progress.md](task-progress.md)를 따른다. 진척 보기에서는 추천을 묻지 않는다. 그래서 ↻·ⓘ·확인 시각·숫자 키가 감춰진다. 추천 보기로 돌아올 때 자료가 바뀌었거나 3분이 지났으면 다시 확인한다.

## 판단 근거 강화 (2026-10-08)

계기: 마지막 답변 끝의 상태 표에 `… 중 선택 대기`, `완료 확인 대기`가 있던 보고 대화를 Mica가 `ask`(0.90)로 판단했다. 사용자 라벨(`기록`)은 제외 조건이 아니었고, 대화 정리로 수정 시각이 바뀌어 최근 대화로 다시 판단됐다. 넘기기는 탭 단위였다. 그래서 같은 대화가 계속 추천됐다.

- **표는 판단 자료가 아니다.** `|`로 시작하는 마크다운 표 줄은 Mica 입력과 인용에서 뺀다. 표만 있는 답변이면 그대로 쓴다.
- **질문은 근거 문장이 있어야 한다.** Mica가 `ask`라고 해도, Mica가 본 끝부분(최대 300자)에 실제 요청 문장(`?`, `할까요`, `주세요`, `주시면`, `알려`, `골라`, `선택해`, `결정해`, `어느 쪽` 등, `ASK_CUE`)이 없으면 `done`으로 본다. 카드 인용은 물음 문장을 먼저 쓰고, 없으면 그 요청 문장을 쓴다.
- **시각은 마지막 턴 기준이다.** 라벨·메모 없는 대화의 최근 3일 판단, 카드의 경과 시간, 같은 순서 안의 정렬, Mica 판단 캐시는 모두 마지막 턴이 끝난 시각(`completedAt`)을 쓴다. 대화 이동·이름 변경으로 바뀐 수정 시각은 쓰지 않는다. 캐시는 같은 턴이라도 끝부분 글이 바뀌면 다시 묻는다.
- **넘기기는 근거와 함께 이 PC에 저장한다.** 카드마다 근거 지문 `version`(상태·턴 끝난 시각·답변 길이·메모·진행 라벨)이 있다. 넘긴 카드는 localStorage `cxm-task-pet-skipped`에 `{id: {v, at}}`로 30일 동안 둔다. 엔진에는 `dismissed: {id: version}`으로 넘기고, 지문이 같은 동안만 뺀다. 그래서 새 답변이 오거나 메모·라벨이 바뀌면 다시 보인다. 엔진은 실제로 뺀 id를 `skipped`로 돌려주고, `넘긴 후보 N개 다시 보기`는 그 카드만 되돌린다.
- 사이드바의 답 필요 점(`thread-status`)은 별도 3갈래 판단이라 이 변경이 적용되지 않는다.

## 모델 설명과 트레이 설정 (2026-10-07)

CodexMemo 트레이의 **펫 설정…**에서 모델 설명 사용 여부, 모델, 추론 강도, Mica 분류 확신도(30~99%), 추천 개수(1~6), 작성 지침(4,000자)을 저장한다. 개인 settings.json의 taskPet 키만 원자적으로 갱신하며 다른 설정은 보존한다.

기본 요청은 GPT-6-Luna · high이며 FAST는 사용하지 않는다. 기존 Codex 로그인/App Server 연결로 설명을 생성한다. Mica는 상태 분류, 코드는 후보 선정과 순서, 생성 모델은 선정된 후보의 다음 행동 설명을 담당한다. 모델 입력은 후보 제목·상태·실제 인용·라벨로 제한하며 모델이 반환한 ID와 순서를 검증한다. 추론 뒤 원본과 설정을 다시 확인한다. 모델 설명은 분류 확신도와 별개이며 정확도 수치를 만들지 않는다.

2026-10-07 현재 앱의 `codex_cli_path()`가 선택하는 OpenAI.Codex_26.930.7945.0의 app/resources/codex.exe와 기존 로그인으로 GPT-6-Luna · high가 실제 설명을 반환했다(3.503초, 가상 후보 한 건). LOCALAPPDATA/OpenAI/Codex/bin의 예전 실행 파일은 같은 모델을 거절하므로 앱의 실행 파일 탐색 경로를 재사용해야 한다. 지원하지 않는 모델이면 추천에 이유를 안내하고 기본 규칙 문구를 표시한다. 모델을 자동 교체하거나 유료 API로 전환하지 않는다.

Codex 화면 오른쪽 위의 작은 펫을 누르면 각 대화가 어떻게 끝났는지, 진행 상태 라벨, 할 일 메모를 읽어 다음에 손댈 대화를 최대 3개 보여 준다. v8까지 기본 동작은 클릭 시 추천이었다. v9부터는 닫힌 동안에도 모델 설명 없이 순위만 확인한다(위 화면 v9 참고).

## 추천 기준 (v5)

라벨만으로는 사용자가 이미 아는 사실을 되풀이할 뿐이어서, 대화의 마지막 턴을 근거로 삼는다. 순서는 고정 규칙이며 패널의 `추천 기준`에서도 볼 수 있다.

| 순서 | 카드 | 근거 |
|---|---|---|
| 1 | 답을 기다려요 | Mica가 마지막 답변이 질문·선택·정보 요청으로 끝났다고 판단 |
| 2 | 중간에 멈췄어요 / 진행이 멈춰 있어요 / 오류로 끝났어요 | 마지막 턴의 실제 상태 |
| 3 | 막혀 있어요 | Mica가 권한·환경 문제로 멈췄다고 판단 |
| 4 | 할 일 메모 | 대화에 연결된 `todo` 메모 |
| 5 | 확인할 일이 남았어요, `검토` 라벨 | Mica가 사용자가 직접 확인·적용할 일이 남았다고 판단 / 라벨 |
| 6 | 그 밖의 진행 상태 라벨 (`요청` 계열 → `진행`) | 라벨 |

- 같은 순서 안에서는 최근 대화부터 보인다.
- 카드에는 실제 문장을 인용한다. 질문은 물음 문장, 남은 확인은 `확인하지 못했다·해야 한다` 문장, 중단된 턴은 사용자의 마지막 요청, 메모 카드는 메모를 보여 준다.
- 라벨만 근거인 카드는 사용자가 정한 라벨 이름을 그대로 배지로 쓴다. 라벨 이름은 바꿀 수 있으므로 뜻을 짐작하지 않는다.
- 완료·보류 라벨(대화가 질문으로 끝났어도), 지금 열린 대화, 이번에 넘긴 대화는 제외한다.
- 라벨·메모가 없는 대화는 최근 3일 안의 것만 보고, 1~3·5번에 해당할 때만 보인다. 보고로 끝난 대화는 끝난 일로 본다.
- 이 도우미의 App Server에서는 Codex 화면에서 실행 중인 턴도 `interrupted`로 보인다. 실제 중단은 끝난 시각(`completedAt`)이 있다. 끝난 시각이 없고 30분 안에 바뀐 대화는 작업 중으로 보고 빼며, 30분 넘게 그대로면 `진행이 멈춰 있어요`(승인 대기·중단 가능성)로 보인다.

## Mica 판단

- 마지막 답변의 끝 문장들(목록 줄 포함, 최대 300자)을 넘기고 `ask / check / blocked / done` 중 하나를 고르게 한다. 사이드바의 3갈래 판단(`thread-status`)과 달리 `check`(남은 확인)를 따로 두어, `직접 확인해야 합니다` 같은 문장이 질문으로 잘못 분류되지 않게 했다.
- 확신 0.8 이상일 때만 판단을 쓴다. 형식이 어긋난 답은 버리고 다음에 다시 묻는다. 같은 대화의 같은 수정 시각은 다시 묻지 않는다.
- 요청별로 `classifier: 'mica'`를 명시한다. 전역 분류기 설정을 바꾸지 않으며 JEV나 다른 모델로 전환하지 않는다.
- Mica를 쓸 수 없으면 턴 상태·라벨·메모만으로 고르고, 답 대기 여부를 확인하지 못했다는 안내를 붙인다. 마지막 턴을 읽지 못하면 라벨과 메모로만 고르고 그 사실을 안내한다. 원본 읽기 실패는 빈 목록과 구별한다.
- 메모·라벨 변경, 메시지 전송, 작업 실행은 하지 않는다.

## 조회와 화면 갱신

- 전체 대화 목록은 읽지 않는다. `thread/list`는 대화 하나당 약 45ms씩 느려져 100개면 4초가 넘는다. 진행 라벨·할 일 메모가 있는 대화는 ID로 `thread/read`(턴 없이)하고, 그 밖에는 최근 3일 안에 바뀐 대화만 `sortKey: 'updated_at'`로 25개씩 읽다가 더 오래된 대화가 나오면 멈춘다. 지워진 대화와 `archived_sessions`에 있는 보관 대화는 뺀다.
- 라벨·메모가 있는 대화 최대 20개와 그 밖의 최근 대화 최대 12개의 마지막 턴을 `thread/turns/list`(`limit: 1`)로 읽는다. `thread/read`로 모든 턴을 읽으면 긴 대화는 수십 MB가 된다.
- 판단 뒤에는 상위 후보 6개만 ID로 다시 읽고 메모 → 최신 라벨 순으로 확인해, 그사이 라벨·메모·제목·수정 시각이 바뀐 후보를 뺀다.
- 실제 자료 기준 한 번 추천에 약 9.5초 걸리던 것이 약 4초로 줄었다(대부분 최근 목록 읽기).
- 같은 메모 목록의 재전송과 카테고리·색상 변경은 추천을 취소하지 않는다. 실제 할 일·진행 상태·자료 읽기 오류의 변경은 새로고침 안내로 표시한다.
- `대화 열기`는 실제 대화 항목·링크를 사용하고, 목록이 접혀 있거나 아직 렌더링되지 않은 로컬 대화는 Codex의 현재 내부 라우터로 연다. 이동을 확인한 뒤 패널을 닫는다.
- `이번엔 넘기기`(카드의 ×)는 근거가 바뀔 때까지 제외한다(아래 '판단 근거 강화'). 넘긴 후보가 있으면 `넘긴 후보 N개 다시 보기`가 나타난다.
- `잠시 숨기기`는 30분 동안 펫을 작은 🐾 손잡이로 줄인다. 손잡이를 누르면 바로 다시 보이고, 30분이 지나면 저절로 돌아온다.
- 펫은 끌어서 옮길 수 있고(조금 흔들린 클릭은 옮기기로 보지 않음), 펫에 초점이 있을 때 Alt+화살표로 16px(Shift 함께 64px)씩 옮긴다. 위치는 이 PC 화면 저장소에 기억하고 창 크기가 바뀌어도 화면 안에 둔다. 펫을 왼쪽에 두면 패널이 오른쪽으로 펼쳐진다. 패널의 `위치 되돌리기`로 오른쪽 위로 돌아간다.
- Codex가 입력창으로 자동 포커스를 옮겨도 펫은 닫히지 않는다. 바깥 클릭·Tab 이동·실제 입력·Escape로 닫을 수 있다. 추천 응답은 30초 뒤 재시도 안내로 전환한다.
- 추천 중 패널을 닫아도 요청은 계속되고, 결과가 오면 초록 점, 실패나 자료 변경은 주황 점으로 알린다. 경고·배지 색은 테마 토큰으로 정의해 Codex의 `html.dark`/`data-theme`을 따른다.

구현은 `labels/task-pet.cjs`(추천 엔진), `labels/task-pet.js`(화면)이고 `src/node/backend.cts`(마지막 턴 읽기) → `shim.js` → 화면 순서로 연결한다.

검증: `npm run check`, `node --test tests/test_task_pet.cjs tests/test_task_pet_catalog.cjs tests/test_mica.cjs`, `python tests/test_task_pet_ui.py`. 실제 설치 적용은 해당 PC의 현재 실행 경로와 파일을 먼저 확인한다.
