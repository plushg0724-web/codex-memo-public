# 기능과 아키텍처

[프로젝트 소개와 설치](../README.md) · [개발과 검증](development.md) · [macOS 안내](../macos/README.md)

공통 메모·라벨·단어장 기능의 세부 동작과 코드 구성을 설명합니다. 트레이, 바로 실행 관리, 전역 단축키는 Windows 구현이며 플랫폼 차이는 프로젝트 소개의 지원 표를 따릅니다.

## 기능

- **구독 사용량 원화 표시** — 사이드바에 현재 할당량 주기의 사용분을 30일 구독료 기준 금액과 %로 표시합니다.
  - 기본 구독료는 **159,000원 / 30일**입니다. 표시를 누르면 원본 할당량 %, 기간별 환산액, 다음 초기화 시각을 확인하고 구독료를 바꿀 수 있습니다.
  - 예: 7일 할당량 32% 사용 → `₩11,872 · 7.47%` (7일 기준액 37,100원). 현재 주기 사용분이며 전체 30일 누계나 실제 청구액이 아닙니다.
  - 이 PC의 Codex 로그인으로 할당량을 읽어 화면이 보이는 동안 15초마다 갱신합니다. 모델을 호출하지 않으며, 여러 기간·상품의 할당량을 더하지 않습니다.
  - 조회 실패·초기화 직후에는 마지막 확인 시각과 이전 값임을 표시합니다. 공식 응답의 사용률 정밀도와 갱신 시점을 따릅니다.
- **단어장·메모** — 대화 글을 드래그하면 Codex 선택 툴바에 버튼이 붙습니다.
  - 같은 앱의 **ChatGPT 채팅**(`/c/<id>`)에서도 드래그 메모·형광펜·단어장을 쓸 수 있습니다. 채팅 메모는 `chat:<id>`로 저장되어 보관함의 **위치로 이동**으로 그 채팅을 엽니다.
  - 짧은 선택(160자 이하): **단어장·메모** → AI 뜻 요약 + 내 메모를 한 창에서 저장 (**뜻+메모 저장** / **메모만 저장**)
    뜻은 **이 문맥에서**의 의미와 **사전적 의미**(번호 목록, 지금 문맥에 해당하는 번호 ◀ 표시, 해당 없으면 '사전에 없는 쓰임')를 함께 보여 줍니다.
    예전에 저장한 단어는 같은 뜻으로 다시 요약될 때 사전적 의미가 채워집니다.
  - 긴 선택: **메모**
  - 같은 단어라도 문맥마다 뜻이 다를 수 있어, 저장된 단어를 다른 문맥에서 열면 AI 가 저장된 뜻들과 비교해
    이 문맥에 맞는 뜻을 고르고 '이 문맥에서의 쓰임'을 보여주거나, 다른 뜻이면 '새 의미'로 정리합니다(같은 문맥이면 AI 호출 없이 바로).
  - **Mica(로컬 판단 모델)** 가 켜져 있으면(127.0.0.1:8010) 뜻 판단을 먼저 Mica 로 합니다(약 0.1초, 비용 없음).
    확신 0.8 이상이면 그 판단을 쓰고 '쓰임 설명 받기' 버튼으로 필요할 때만 GPT 를 부릅니다. 확신이 낮거나 Mica 가 꺼져 있으면 GPT 로 판단합니다.
    마우스 올림 카드의 뜻 순서도 Mica 로 정합니다(같은 단어·문단은 기억).
  - 단어 → 핵심 뜻 → 부가 설명·예문 순서로 표시하며, 원문 문맥은 접어서 필요할 때 엽니다.
  - 저장된 뜻은 **다시 분석**하거나 **추가 질문**을 이어 갈 수 있습니다. 결과를 확인한 뒤 **분석 결과 저장** 또는 **추가 답변 저장**으로 현재 항목에 반영합니다.
    문단 옆 체크박스로 고른 내용은 마우스 올림 카드 맨 위에 표시하며, 선택과 질문·답변도 단어장 데이터에 저장합니다.
  - **보관함**은 작성 화면과 별도로 엽니다. 전체 / 단어 / 메모 필터, 통합 검색, 메모 수정·복사·삭제를 지원합니다.
    작성 중 보관함을 열었다 돌아와도 메모와 뜻 편집 내용이 유지됩니다.
  - 메모 카드의 **위치로 이동**: 메모한 대화를 열고 그 글로 스크롤해 잠깐 반짝입니다. 대화가 삭제됐으면 '대화 없음 (삭제됨)', 보관한 대화면 '보관된 대화'로 표시합니다.
- **바로 실행 (Windows)** — 트레이의 **바로 실행 (Windows)** 에서 자주 쓰는 프로그램(BAT·CMD·PS1·EXE·LNK)을 켭니다.
  누르면 켜고, 이미 켜져 있으면(포트 응답) 등록한 웹 화면을 엽니다. **바로 실행 관리…** 에서 추가·수정·삭제·순서 바꾸기.
  창 없이 실행하고 출력은 `%LOCALAPPDATA%\CodexMemo\launch-logs` 에 남깁니다. 예전 '바로실행' 실행기의 목록은 처음 한 번 가져옵니다.
- **공통 설정** — 라벨 메뉴의 **설정…** 또는 단어장·보관함의 설정 버튼에서 엽니다.
  - **라벨**: 진행 상태·카테고리의 이름, 색상, 설명, 배지 모양을 편집하고 저장합니다.
  - **단어장·메모**: 요약 모델을 먼저 고르고, 그 모델이 지원하는 추론 강도를 선택합니다.
    계정에서 쓸 수 있는 모델을 `codex app-server`의 `model/list`로 받습니다(기본 GPT-6-Luna · high).
    **FAST**(Codex 의 Fast, `service_tier="priority"`: 더 빠르지만 사용량 증가)는 기본으로 켜져 있고 끌 수 있습니다.
    **요약 작성 지침**에서 뜻·쓰임·예문·태그를 어떻게 쓸지 고쳐 쓸 수 있습니다(안전 문구와 JSON 출력 형식은 고정, 기본 지침으로 복원 가능).
  - **자동 판단**: 카테고리 추천·대화 상태·메모 분류·단어 뜻 판단의 기준과 다시 판단을 관리합니다.
  - 모델·추론 강도·FAST와 자동 판단 기준은 변경할 때 저장되고, 작성 지침은 **지침 저장**으로, 라벨 편집은 저장 버튼으로 적용합니다.
- **형광펜** — 메모한 문장은 CSS Custom Highlight API 로 칠해져 스크롤해도 지연이 없습니다.
  선택한 글과 앞뒤 32자 문맥(W3C TextQuoteSelector 방식)을 저장해 메모한 그 자리만, 메모를 쓴 대화에서만 칠합니다.
  칠한 곳을 클릭하면 메모를 보고 고칠 수 있습니다.
- **Google 시트 (단어·메모 표)** — 트레이의 **Google 시트 연결…** 을 누르면 내 Google Drive 에 'Codex 단어장·메모' 시트를 만들고
  지금까지의 단어·메모를 채운 뒤, Space 에 시트 링크 페이지를 만듭니다. 이후 단어·메모를 저장할 때마다 행이 자동으로 추가됩니다.
  열은 머리글 이름으로 찾으므로 열을 더 붙이거나 순서를 바꿔도 됩니다(DB 처럼 사용). 시트 정보는 각자의 `labels/settings.json` 에만 저장됩니다.
  ChatGPT 에 Google Drive 가 연결돼 있어야 하며, 메모를 고치거나 지워도 시트의 행은 그대로 둡니다(쌓기 전용).
  연달아 저장하면 연결을 2분간 재사용해 두 번째부터는 약 1초 만에 행이 추가됩니다.
- **단어 본문 표시** — 단어장에 저장한 단어를 대화 본문에서 점선 밑줄과 옅은 배경으로 표시합니다(CSS Custom Highlight, 본문을 고치지 않음).
  대소문자·전각/반각을 가리지 않고, 'SELinux가'·'DPAPI로'처럼 바로 붙은 조사도 인식합니다. 코드·입력란·왼쪽 목록은 표시하지 않습니다.
  보관함의 **본문 표시** 에서 밑줄+배경 / 점선 밑줄 / 배경 / 끄기를 고릅니다(이 PC 의 Codex 화면에 저장). 끄면 마우스 올림·클릭 카드도 쉽니다.
- **마우스 올림 카드** — 저장된 단어(점선 밑줄)나 메모한 글(노란 형광펜)에 마우스를 올리면 저장된 뜻·예문과 그 자리의 메모를 카드로 보여줍니다. 클릭하면 기존처럼 자세히 보기.
  미리보기와 클릭한 뜻 카드에서 **학습 상태**(미학습 / 복습 필요 / 숙지함)를 선택하면 즉시 저장됩니다. 여러 뜻의 상태는 각각 변경할 수 있습니다.
- **대화 카테고리 추천 (Mica)** — 카테고리가 없는 대화에 개발·디버그·노하우·행사신청 등을 점선 칩으로 추천합니다.
  진행 상태만 지정된 대화에도 추천하며, 카테고리를 선택해도 진행 상태는 유지됩니다. 판단 기준은 **설정 → 자동 판단**에서 조절합니다(기본 0.6).
  기준 이상의 추천은 클릭해 지정하고, 기준 미만은 후보 메뉴에서 확인합니다. 오른쪽 클릭하면 추천을 숨깁니다.
  대화 내용과 기존 카테고리 지정 예시를 참고하며, 완료·보류 여부와 작업 주제를 구분하도록 판단합니다.
- **진행 상태와 카테고리** — 대화 제목 앞에 두 배지를 독립적으로 표시합니다. 예를 들어 `검토`와 `개발`을 함께 지정할 수 있습니다.
  진행 상태는 좁은 세로 배지, 카테고리는 가로 배지로 표시하고 미지정 배지는 `＋`로 줄입니다. 전체 이름은 메뉴와 마우스 올림 설명에서 확인합니다.
  선택 메뉴에서 진행 상태와 카테고리를 각각 설정·해제하며, 한쪽을 바꿔도 다른 쪽은 유지됩니다.
  기존 요청·진행·검토·완료·보류 라벨은 진행 상태로, 그 외 기존 라벨은 카테고리로 읽습니다. 라벨 ID·이름·색상은 유지합니다.
  라벨 설정에서 새 라벨의 종류를 선택할 수 있습니다. 기존 라벨의 종류는 저장된 배정을 보존하기 위해 변경하지 않습니다.
  자동으로 표시되는 답변 필요·막힘 표시는 별도 안내이며, 사용자의 완료 확인이나 수동 진행 상태를 대신하지 않습니다.
- **트레이 아이콘 (Windows)** — 메모 목록(Ctrl+Alt+M: Codex 를 앞으로 가져와 보관함을 메모 필터로 엶), Codex 화면 새로 고침, Codex 메모 모드로 다시 시작, 메모 폴더 열기.

Codex Labels는 이 프로젝트 작성자가 직접 개발한 이전 이름의 프로그램입니다.
`labels/vendor/`에는 그 화면·저장 코드를 이어서 사용하며, 연결을 바꾼 곳에 `[codex-memo 변경]` 표시가 있습니다.

## 저장된 단어 다시 분석·추가 질문

등록된 단어를 드래그하면 **맥락분석** 버튼이 표시됩니다. 같은 문장에서는 저장된 분석을 보여 주고, 새 문장에서는 분석 결과를 확인한 뒤 같은 단어에 추가 저장할 수 있습니다. 여러 뜻이 있으면 저장 대상을 직접 선택합니다.
기본 맥락분석과 추가한 문장별 분석은 체크박스로 미리보기 표시를 켜거나 끕니다. 체크 해제는 분석 내용을 삭제하지 않습니다.

저장·편집·편집 취소·새 의미 추가·다시 분석·원문은 상단 고정 영역에서 조작합니다. 맥락분석·품사·사전 뜻·참고·예문·추가 설명 문단 옆의 **삭제**와 **재분석**은 해당 문단만 바꾸며, 결과를 확인하고 **변경 저장**을 눌러 반영합니다. 저장 전에는 **원본으로 되돌리기**로 취소할 수 있습니다.

새 단어 요약에는 자세한 설명·쉬운 설명·추가 예시도 함께 요청하며, 받은 설명은 일반 추가 답변으로 저장됩니다. 다시 분석할 때 기존 추가 답변은 보존하고 아직 없는 기본 설명만 추가합니다.

1. **보관함 → 단어**에서 저장된 항목을 열고 수정할 뜻을 선택합니다.
2. **다시 분석**을 누르면 현재 단어장 모델 설정으로 뜻과 설명을 새로 작성합니다. 화면에서 결과를 확인합니다.
3. **분석 결과 저장**을 누르면 선택한 항목의 분석 내용을 교체합니다. 원문 문맥과 출처 등 기존 항목 정보는 유지합니다.
   다시 분석해도 이전에 저장한 추가 질문·답변은 남습니다.

더 알고 싶은 내용은 **추가 질문**에 입력합니다. 현재 Codex 로그인으로 연결하고, 단어장에 설정한 모델이
현재 분석 내용과 이전 질문·답변을 참고해 답합니다. 새 답변도 먼저 화면에서 확인하고 **추가 답변 저장**으로 반영합니다.
추가 질문·답변은 항목당 최대 20개를 보관하며, 질문은 2,000자, 답변은 6,000자까지 저장합니다.

저장된 항목의 문단 옆 체크박스는 선택 즉시 저장되며, 고른 문단이 **마우스 올림 카드 맨 위**에 표시됩니다.
신규 요약·재분석 결과·편집 중인 내용의 체크박스는 해당 내용을 저장할 때 함께 반영합니다.
상세 화면의 원래 문단 순서는 유지합니다. 예전에 저장한 단어에도 체크박스가 표시되므로 다시 분석하지 않고 선택할 수 있습니다.
재분석이나 편집으로 문단의 내용이 바뀌면 해당 문단의 이전 고정 선택은 해제되므로, 새 내용을 확인하고 다시 선택합니다.
저장한 선택과 추가 질문·답변은 다시 열어도 유지되며 **계정 백업·복원**에도 포함됩니다.

새 요약을 저장하지 않은 상태에서도 보관함을 열람하고 **작성으로 돌아가기**로 복귀할 수 있습니다.
다른 화면에 초안이나 편집 내용이 남아 있으면 새 분석·추가 질문을 시작할 수 없습니다.
먼저 저장하거나 **요약 결과 버리기** / **원본으로 되돌리기**로 정리하세요. 현재 초안을 다시 요약할 때는 폐기를 확인합니다.

## 모델이 직접 관리 (MCP)

Codex 대화에서 "이 대화들 완료로 바꿔줘", "개발 대화들을 회사내규 프로젝트로 옮겨줘", "방금 바꾼 거 되돌려줘"처럼 말하면
모델이 라벨·메모·단어장·대화 위치를 바꾼다. 바꾼 내용은 되돌릴 수 있고, 지우기는 분명히 요청했을 때만 한다.
연결 방법과 도구 목록은 [docs/memo-mcp.md](memo-mcp.md).

## 대화 중 빠른 분류 (MCP)

`labels/mica-mcp.cjs`를 stdio MCP 서버로 연결하면 Codex 등에서 선택·예/아니오·척도 점수·일괄 분류 도구를 쓸 수 있습니다.
기본은 무료 로컬 분류기이며 `mica`·`jev`·`both`를 선택할 수 있습니다(JEV는 클라우드로 글을 전송).
확신 0.8 미만은 보류하며 글 생성이나 작업 완료 판정에는 쓰지 않습니다. npm 의존성 추가 없이 별도로 실행하고 개인 메모나 앱에는 연결하지 않습니다.
연결은 사용자가 직접 설정합니다: [설정·도구 예시](mica-mcp.md), [에이전트 사용 지침](mica-skill.md).

## 호스트 연결과 기존 데이터 호환성

- 기본 디버그 주소는 `127.0.0.1:9233`입니다. 이 포트가 열려 있는 동안 같은 컴퓨터의 다른 프로그램도 호스트 화면에 접근할 수 있습니다.
- Codex 업데이트로 화면 구조가 바뀌면 동작하지 않을 수 있습니다.
- Codex Labels 앱과 동시에 실행하지 마세요(같은 라벨·단어장 파일을 사용).
- 기본 모델이 아닌 모델로 저장한 단어는 원래 Codex Labels 앱에서 읽지 못합니다.


## 계정 백업 · 복원 (추가 기능)

Windows는 트레이의 **계정 백업 · 복원…**, macOS는 메뉴 막대의 **지금 계정에 백업…** 또는 **계정 백업에서 복원…**에서 사용합니다.

- **지금 백업**: 현재 ChatGPT 계정의 개인 Space 페이지에 라벨 정의, 대화별 진행 상태·카테고리 지정, 단어장, 메모, 공통 설정을 원본 JSON으로 저장합니다.
  단어장의 추가 질문·답변과 마우스 올림 카드에 고정한 문단 선택도 함께 저장합니다.
- **목록 새로 고침**: 계정에서 `CodexMemo Backup` 페이지들을 찾아 표시합니다. 다른 PC에서도 같은 계정·작업 환경에서 찾을 수 있습니다.
- **선택한 백업 복원**: 현재 데이터를 교체합니다. 교체 전 파일은 사용자 데이터 폴더의 `restore-backups`에 보관합니다. 복원은 자동 병합하지 않습니다.
- **자동 백업**: 사용자가 켠 경우에만 5분 간격으로 변경된 데이터를 백업합니다. 자동 복원·오래된 백업 자동 삭제는 하지 않습니다.
- 백업은 개인 페이지로 생성하며 임의의 공유 Space를 선택하지 않습니다. 로그인 파일·제어 서버 토큰·Google 시트 연결·PC별 프로그램 경로는 백업하지 않습니다.
- 공통 설정은 단어장 모델·추론 강도·FAST, 요약 작성 지침, 자동 판단 기준, 분류기 선택입니다. 화면 localStorage에만 있는 표시 설정은 포함하지 않습니다.
- 텍스트 스냅샷은 80 KB까지입니다. 이를 넘으면 오류를 표시하고 파일을 자르지 않습니다.
- 모델 생성 없이 App Server의 Space 도구를 직접 호출합니다. 계정의 Space 사용 가능 여부와 App Server 도구 지원에 따라 연결 오류가 발생할 수 있습니다.


### 백업과 런타임의 처리 방식

- 계정 백업의 형식 처리, 로컬 파일 처리, Space 통신, 작업 상태·자동 실행을 별도 모듈로 분리했습니다.
- 설정과 백업 원본 JSON은 파일이 바뀐 경우에만 다시 읽습니다. 같은 설정 저장은 파일 쓰기를 생략합니다.
- 백업 목록은 30초 캐시를 사용하며 직접 새로 고침은 서버에서 다시 읽습니다. 페이지 중복과 일부 검색 결과를 구분합니다.
- 복원은 원본 데이터를 먼저 보관하고 교체 실패 시 이전 파일을 복구합니다. 복원 완료 후 화면 갱신 오류는 완료 결과의 안내로 구분합니다.
- 자동 백업은 작업이 끝난 뒤 다음 실행을 예약합니다. 실패가 반복되면 재시도 간격을 최대 1시간까지 늘립니다.
- 백업 창은 시각·기기·항목 수 표와 선택 유지, 닫았다 다시 열기, 늦은 응답 구분, 대기 시간 초과 처리를 제공합니다.
- 도우미 종료 시 CDP 연결·Node 백엔드·App Server·핫키·타이머·구독을 정리합니다. 응답이 끝난 요청은 대기 목록에서 제거합니다.
- 메모 개별 조회는 전체 목록 복사를 생략합니다. 같은 내용 저장 시 편집 완료 알림은 계속 전달합니다.
- 트레이 이벤트는 종류별 처리기 표로 처리합니다. 한 처리기나 트레이 제목 갱신에서 오류가 나도 이후 이벤트 처리가 멈추지 않습니다.
- Codex 가 꺼져 있을 때 앱에 포함된 `codex.exe` 위치를 Windows 패키지 API로 찾습니다(PowerShell 약 0.5초 → 수 ms). API를 쓸 수 없는 환경에서만 PowerShell을 사용합니다.
- 메모 저장은 JSON을 한 번에 만들어 씁니다(메모 1,000개 기준 약 3배 빠름). 읽기용 `memos.md`는 임시 파일로 쓴 뒤 교체하며,
  다른 프로그램이 파일을 잠가 쓰지 못해도 `memos.json` 저장과 화면 알림은 정상 처리합니다(다음 저장 때 다시 씀).
- 바로 실행 관리 창은 등록한 포트를 동시에 확인합니다. 닫힌 포트마다 약 0.15초씩 차례로 기다리지 않습니다.
- 업데이터는 배포 압축의 `runtime-manifest.json`(`requiredFiles`)으로 필수 실행 파일을 확인합니다. 매니페스트가 없는 예전 배포는 빌드된 Node 모듈 목록을 확인합니다.
- 제어 서버는 거절 응답(열쇠 불일치 등) 전에도 요청 본문을 읽습니다. MCP 쪽이 연결 오류 대신 안내 문구를 받습니다.
- 대화 상태 표시는 한 번의 계산에서 목록 조상 요소의 스타일·잘림 영역을 공유하고(300행 기준 약 27배 빠름), 위치 읽기와 표시 변경을 나눠 처리합니다.
  답변 작성 중 대화 본문이 스크롤될 때는 다시 계산하지 않습니다.
- 단어 본문 표시의 설정 연결은 단어장·설정 창이 열려 있을 때만 확인합니다(답변 작성 중 추가되는 요소마다 조상·자식을 찾지 않음).

## 캐시와 상태 관리

- 단어장 백엔드의 요약·재분석·추가 질문·저장·취소를 `vocabulary-service.cts`로 분리했습니다. 변경된 단어장 버전에서만 뜻 인덱스를 다시 만들고, 동일 단어·문맥의 진행 중인 정렬 요청은 함께 사용합니다. 취소되거나 이전 버전에서 시작한 응답은 새 초안·정렬 캐시를 덮어쓰지 않습니다.
- 보관함 검색은 항목 배열이 바뀔 때 검색 문자열과 표시용 메타정보를 한 번 계산합니다. 검색어·즐겨찾기·학습 상태 필터 변경 때 해당 값을 다시 사용합니다.
- 바로 실행 관리 창은 목록을 먼저 그리고 포트 상태를 백그라운드에서 갱신합니다. 진행 중 확인 작업은 하나로 유지하고, 목록 변경 요청은 가장 최근 것만 이어서 처리합니다. 행을 재사용하므로 선택과 스크롤을 유지합니다.
- 계정 복원이나 외부 수정으로 `memos.json`이 바뀌면 캐시와 읽기용 `memos.md`를 갱신한 뒤 화면에 알립니다. 시작할 때 누락되거나 오래된 Markdown도 다시 만듭니다. 변경 없는 주기적 확인에서는 JSON 읽기·Markdown 쓰기를 생략합니다.

성능 배수·시간은 기존 합성 데이터 측정의 참고값이며 실제 대화 규모와 컴퓨터에 따라 달라집니다. 비교 방법은 [개발과 검증](development.md)의 성능 검사에 있습니다.
